# 中文学习 Agent MVP 最小可行技术实现计划

本文档基于 `docs/答疑MVP产品需求文档（PRD）.md`、`prompt/chatbot_sys_prompt.md` 和当前最小知识库整理，用于指导两小时内完成一个可运行、可验证的最小技术闭环。

## 1. 实现目标

最小可行技术目标不是完成完整教学系统，而是完成一个本地可运行的 1v1 中文学习 Chatbot：

- 学生可以在网页聊天框中连续提问。
- Agent 通过流式输出回复。
- Agent 必须使用 RAG 检索教材范本和能力边界。
- Agent 回复必须基于 HSK4 向 HSK5 延伸，不明显超纲。
- Agent 面对错误句子时优先引导学生自我修正，而不是第一次直接给答案。
- 系统保存聊天记录、检索结果和基础运行数据，方便后续复盘。

### 2.1.1 GCP GenAI 模型调用适配层

LLM 和 embedding 都使用 GCP GenAI，不使用 OpenAI SDK 或 OpenAI 模型名。代码中新增 `app/model_client.py`，统一封装：

```text
embed_texts(texts: list[str]) -> list[list[float]]
stream_reply(input_text: str) -> Iterator[str]
```

调用方只依赖这两个函数，不在 RAG 或聊天业务逻辑中直接调用 SDK。GCP GenAI 配置通过环境变量提供：

```text
GEMINI_API_KEY            # 如本地 SDK 需要
GCP_LLM_MODEL=gemini-3.8-flash
GCP_EMBEDDING_MODEL=gemini-embedding-2
```

embedding 调用方式：

```python
from google import genai

client = genai.Client()

result = client.models.embed_content(
    model="gemini-embedding-2",
    contents="What is the meaning of life?"
)

print(result.embeddings)
```

LLM 流式调用方式：

```python
from google import genai

client = genai.Client()

stream = client.interactions.create(
    model="gemini-3.8-flash",
    input="Explain how AI works",
    stream=True
)
for event in stream:
    print(event)
```

实现要求：

- embedding 构建和 query embedding 都走 `embed_texts`。
- 聊天回复生成走 `stream_reply`。
- `stream_reply` 内部使用 `client.interactions.create(..., stream=True)`。
- 后端将 GCP GenAI stream event 转换为 SSE 文本片段返回前端。
- 数据库记录 `model`、`embedding_model`、`provider = gcp`。
- 不在业务逻辑中硬编码具体模型名。

### 2.3 Embedding 构建

- 使用 GCP GenAI embedding model，默认 `gemini-embedding-2`，通过 `GCP_EMBEDDING_MODEL` 配置。
- 首次启动时为所有 chunk 生成 embedding。
- embedding 写入 SQLite。
- 后续启动复用已有 embedding。
- 需要记录 provider、embedding model、源文件路径、chunk hash，源文件变化时重新生成对应 chunk。

### 2.4 双路 RAG 检索

必须拆成两个 index：

```text
teaching_index
- 发展汉语高级阅读1.md
- 发展汉语高级阅读1参考答案.md

level_index
- HSK4词汇.md
- HSK5词汇.md
- HSK语法1-5.md
```

每轮用户输入：

```text
用户问题
→ 生成 query embedding
→ 查 teaching_index top 3
→ 查 level_index top 3
→ 拼接 runtime context
→ 生成回复
```

查询阶段可先用 Python 全量内存余弦相似度，不引入 Pinecone、Milvus、Qdrant、FAISS。当前知识库规模很小，全量扫描足够。

## 3. RAG 实施细则

### 3.1 RAG 语料职责

教材范本不是能力边界，能力边界也不是教学范本。两者职责必须分开。

`teaching_index` 负责：

- 找教材原文。
- 找阅读题。
- 找参考答案。
- 找相似表达。
- 给 Agent 提供教学范本、上下文和例句来源。

`level_index` 负责：

- 判断词汇是否属于 HSK4 或 HSK5。
- 判断语法点是否在 HSK4 到 HSK5 延伸范围内。
- 限制 Agent 不主动使用过难词汇和复杂语法。

### 3.2 教材 chunk 策略

教材文件不要只按固定字符粗切。优先按语义结构切：

- 文章标题。
- 自然段。
- 注释。
- 题目。
- 选项。
- 参考答案。

建议 metadata：

```json
{
  "index_name": "teaching_index",
  "source": "知识库min/教材/发展汉语高级阅读1.md",
  "chunk_type": "textbook_article | exercise | answer",
  "heading": "文章一 休闲与游戏",
  "content": "..."
}
```

如果来不及做精细 parser，两小时版本允许按标题和段落切分，但必须保留 `source`、`heading`、`chunk_type`。

### 3.3 水平表 chunk 策略

词汇表优先按教学边界分组，embedding 辅助：

- HSK4 词汇每 15 个词条切成一个 `vocabulary_group`。
- HSK5 词汇每 8 个词条切成一个 `vocabulary_group`。
- 每个 chunk 保留组内词、拼音、英文义项、例句，以及 `item_no_start` / `item_no_end` / `terms`。

语法表按单个语法项目切：

```json
{
  "index_name": "level_index",
  "source": "知识库min/水平表/HSK语法1-5.md",
  "chunk_type": "grammar",
  "hsk_level": "4",
  "heading": "时间状语",
  "content": "主语 + 时间状语 + 动词..."
}
```

当前实现会解析语法表格行，尽量保留等级、语法点、结构和例句。这样既能减少词汇逐条 embedding 的成本，又能让回答拿到足够清晰的能力边界。

### 3.4 不超纲定义

MVP 中“不超纲”定义为：

```text
HSK4：可以自由使用。
HSK5：可以少量使用，用于向目标水平延伸；每次最多引入 1-2 个新点，并用简单中文解释。
HSK6+：默认不主动使用，除非用户主动问到，或教材原文中必须出现。
```

Agent 生成回复时应遵守：

- 默认用 HSK4 可理解中文解释。
- 必须引入 HSK5 词汇或语法时，要给简单解释。
- 不要使用明显学术化的语言学术语。
- 例句优先使用学生已学过或 HSK4 可理解内容。

### 3.5 检索结果拼接

每轮 runtime context 控制在小范围内：

```text
教学范本 top 3
能力边界 top 3
最近 4-6 轮对话
学生画像摘要
本轮问题
```

不要把完整教材、完整词汇表或完整 sys prompt 每轮塞入模型。

## 4. Sys Prompt 优化

详细策略见 `docs/SysPrompt优化与拆分策略.md`。技术实现计划中只保留最小落地要求。

MVP 不应每轮完整注入 `prompt/chatbot_sys_prompt.md`。该文件作为源文档保留，实际运行时拆成：

```text
Kernel Prompt：每轮常驻，保留不可变教学原则。
Workflow Prompt：按问题类型动态加载。
Runtime Context：每轮拼接学生画像、历史对话、RAG 教材 reference 和水平边界。
```

最小实现要求：

- 提炼 `prompt/kernel.md`，控制在 1200-1800 中文字。
- 新增 workflow prompt：
  - `vocabulary_question.md`
  - `grammar_question.md`
  - `sentence_correction.md`
  - `reading_expression.md`
  - `expression_naturalness.md`
- 两小时版本先用关键词规则判断 `problem_type`。
- 每轮 prompt 只拼接当前问题相关的 workflow 和 RAG context。
- 输出仍必须满足：全中文、不超纲、优先引导、一次一个核心问题、自然亲和。

## 5. 最小验收用例

### 5.1 语序纠错

输入：

```text
我昨天去图书馆学习中文早上。
```

期望：

- 检索到时间状语或相近语法边界。
- 回复不直接给完整答案。
- 引导学生注意“早上”的位置。

### 5.2 词义解释

输入：

```text
“方便”是什么意思？
```

期望：

- 可以直接解释词义。
- 使用简单中文。
- 给一个短例句。

### 5.3 表达自然度

输入：

```text
我可以说“我方便明天去”吗？
```

期望：

- 不只回答“可以/不可以”。
- 引导学生观察“方便”和时间的位置。
- 必要时给选项或填空。

### 5.4 教材问题

输入：

```text
文章一里“休闲的价值不言而喻”是什么意思？
```

期望：

- 检索到 `发展汉语高级阅读1.md` 文章一。
- 用 HSK4 可理解中文解释。
- 不输出长篇理论。


## 6. 非目标

当前阶段不做：

- 多用户系统。
- 登录注册。
- 教师管理后台。
- 完整 HSK 备考系统。
- 自动学习计划。
- 自动周报。
- 语音输入输出。
- 复杂多 Agent 编排。
- 外部向量数据库。
- 长篇作文完整批改。

## 7. MVP 完成定义

满足以下条件即可认为最小技术实现完成：

- 本地页面可访问并支持多轮聊天。
- Agent 使用流式输出。
- 系统使用 embedding 检索 `teaching_index` 和 `level_index`。
- Agent 回复受 HSK4 到 HSK5 能力边界约束。
- 纠错类问题优先引导学生自我修正。
- 聊天记录、检索 chunk 和模型信息被保存。
- 至少通过本文档中的 4 个验收用例。
