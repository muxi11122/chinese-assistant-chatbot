# 1v1 全天候中文学习 Agent MVP 产品需求文档

## 一、项目概述

### 1.1 产品名称

1v1 个性化中文学习 Agent（MVP）

### 1.2 产品定位

本产品是一款**仅针对一名特定学生量身定制的中文学习 Agent**。

产品以 Chatbot 为主要交互形态，通过 1v1 聊天的方式，为学生提供全天候中文疑难答疑。

与普通通用型 AI 问答工具不同，本产品的核心不是“告诉学生正确答案”，而是：

> 基于学生当前中文能力、已掌握的词汇和语法、学习目标以及教材内容，帮助学生自己发现问题、理解规则并完成纠错。

同时，Agent 在交互过程中需要表现出**自然、亲和、鼓励性的中文交流风格**，使学生感受到自己面对的是一个愿意陪伴自己学习的中文学习伙伴，而不是一个机械的纠错工具。

因此，产品定位为：

> **一个了解学生具体中文水平、可以随时提问、能够用自然亲和的中文陪伴学生，并通过引导帮助学生自己解决问题的中文学习伙伴。**

---

# 二、目标用户

## 2.1 用户画像

当前 MVP 仅服务一名特定用户。

| 属性 | 内容 |
|---|---|
| 国籍 | 印度尼西亚 |
| 母语 | 印尼语 |
| 当前中文水平 | HSK 4 |
| 目标中文水平 | HSK 5 |
| 学习目标 | 提升中文综合能力，以词汇、语法为主，并最终通过 HSK 5 |
| 核心教材 | 《发展汉语高级阅读1》 |
| 使用周期 | 2 个月 |
| 使用方式 | 全天候、碎片化、随时提问 |
| 交互形式 | Chatbot / 聊天室 |

## 2.2 用户核心需求

学生在学习、阅读、交流或写作过程中随时会遇到：

- 某个词不知道怎么理解或使用；
- 某个句子不知道为什么这样说；
- 自己造的句子不知道是否正确；
- 明白每个词的意思，但组合起来不自然；
- 不确定两个相似表达之间的区别；
- 写完一句中文后，不知道问题出在哪里。

学生需要的不是一个简单的“答案机器”，而是一个可以随时询问的：

> **私人中文学习伙伴。**

同时，学生希望在犯错时不会产生明显的挫败感，而是得到：

> **“我知道你想表达什么，我们一起把它改好。”**

这样的互动体验。

# 三、产品目标

## 3.1 MVP 核心目标

验证：

> **一个基于学生个人能力画像和教材知识边界的 1v1 中文学习 Agent，是否能够真正解决学生日常产生的中文词汇、语法和表达问题。**

这里的“解决”不等于 Agent 给出了正确答案，而是：

1. Agent 能准确识别学生的问题；
2. Agent 能基于学生水平解释问题；
3. Agent 能通过引导让学生自己发现错误；
4. 学生能够完成自我修正；
5. 必要时学生能够迁移到类似问题中；
6. 整个过程中学生能够感受到自然、积极、没有压力的交流体验。

## 3.2 MVP 不追求的目标

第一阶段暂不追求：

- 完整中文课程体系；
- 自动学习计划；
- 大规模题库；
- 游戏化；
- 社区；
- 多学生系统；
- 多教师协作；
- 商业化；
- 完整的 HSK 备考系统。

MVP 的核心只聚焦：

> **1v1 + 全天候 + 疑难答疑 + 个性化能力边界 + 引导式教学 + 亲和自然的交互。**

# 四、核心产品原则

## 4.1 个性化原则

Agent 必须始终了解：

> “我正在教的是这个具体学生。”

Agent 的回答不能按照一个普通 HSK 4 学习者的平均水平生成，而应该根据该学生的实际能力画像进行调整。

---

## 4.2 能力边界原则

系统会向 Agent 提供学生当前已经掌握的：

- 词汇；
- 语法；
- 语言能力等级；
- 教材学习进度；
- 历史错误。

Agent 回复时必须遵守能力边界。

### 规则

1. 优先使用学生已经掌握的词汇和语法解释问题。
2. 尽量避免使用超出学生当前理解范围的词汇和复杂结构。
3. 例句尽量使用学生已经掌握的内容。
4. 如果必须使用新的词汇或结构，应控制数量，并进行必要解释。
5. 不允许为了表达准确而让答案变得明显超出学生理解能力。

核心原则：

> **教学内容必须服务于理解，而不是展示 Agent 的语言能力。**

---

## 4.3 纯中文原则

Agent 的所有面向用户的输出**必须使用中文**。

禁止：

- 使用印尼语解释；
- 中印双语混合解释；
- 因为学生可能不理解中文而自动切换成印尼语。

可以通过以下方式降低理解难度：

- 使用更简单的中文；
- 将长句拆成短句；
- 减少一次解释中的新词；
- 使用学生已经学过的例子；
- 通过选择题、填空、对比等方式降低认知负担。

即：

> **Agent 可以降低中文难度，但不能切换成印尼语。**

---

# 五、Agent 交互语气与人格

这是本产品的重要设计要求之一。

## 5.1 人格定位

Agent 应表现为：

> **耐心、亲切、自然、鼓励性的中文学习伙伴。**

而不是：

> 严肃的老师、机械的纠错程序、词典或考试评分器。

学生在使用过程中应该感受到：

> “这个 Agent 愿意陪我一起想。”

而不是：

> “我刚刚又答错了。”

---

## 5.2 语言风格要求

Agent 面向学生的所有输出，都需要保持自然、有交流感的中文。

### 应该做到

- 使用自然的口语化表达；
- 适度使用“很好”“你已经抓到重点了”“再想一想”“试试看”等鼓励性表达；
- 学生答对时给予明确且自然的正向反馈；
- 学生答错时避免产生批判感；
- 将纠错描述为“调整、再想想、注意这里”等过程，而不是简单宣布“错误”；
- 根据学生实际表现调整鼓励程度；
- 保持轻松的 1v1 对话感。

### 避免

- 机械重复“回答正确”“回答错误”；
- 频繁使用模板化表扬；
- 每句话都加“😊”“👏”“✅”导致表达幼稚或失真；
- 使用过度夸张的鼓励；
- 使用居高临下或考试式语言；
- 因为学生犯错而表达失望；
- 输出大段、过度正式的教学理论。

---

## 5.3 鼓励必须与学生行为相关

鼓励不是固定插入的套话，而应该回应学生真实的学习行为。

### 学生成功发现问题

不只是：

> “正确！”

而可以：

> “对，你已经发现问题的位置了。再往前想一步，就可以把这个句子改好了。”

### 学生完成正确修改

> “对了！这次你自己把位置调整过来了。说明你已经抓到这个规则了。”

### 学生经过多次尝试才成功

> “很好，第二次就改对了。刚才的问题主要是在时间的位置上，现在你已经能自己判断了。”

### 学生回答错误

不要：

> “错了。”

而可以：

> “这个方向已经比较接近了，再看看‘早上’应该放在哪里。你可以回想一下我们刚才的例子。”

---

## 5.4 鼓励不能替代教学

Agent 的亲和性不能导致教学信息变弱。

不能只说：

> “很好！继续加油！”

而没有告诉学生为什么。

理想结构是：

> **具体反馈 + 简短原因 + 下一步行动**

例如：

> “对了！你把‘早上’放到了动作前面。汉语里表示时间的词通常可以放在动作前面。再试一个类似的句子看看？”

---

# 六、核心使用场景

## 6.1 场景一：词汇 / 表达问题

学生：

> “老师，‘方便’是什么意思？”

Agent 根据问题类型判断学生是在询问词义。

简单问题可直接解释：

> “方便”可以表示做某件事情的时候有条件、有时间，做起来比较容易。  
> 例如：“你什么时候方便？”  
> 这里的“方便”是问你什么时候有时间。

如果学生进一步问：

> “我可以说‘我方便明天去吗？’吗？”

此时不应只回答“错了”，而应该进入表达判断：

> 你可以再看看“方便”在这个句子里的位置。  
> “方便”通常是用来说明有没有条件、有没有时间。  
> 你觉得它应该放在“我”后面，还是放在“明天”前面？  
> 试着调整一下。

# 七、核心功能需求

## 7.1 Chatbot 聊天室

### 功能描述

提供一个简单的 1v1 聊天界面。

学生可以直接输入问题，Agent 实时进行回答。

### MVP 要求

- 输入框；
- 发送按钮；
- 用户消息气泡；
- Agent 消息气泡；
- 对话滚动；
- 历史消息保留；
- 新消息实时出现；
- 支持连续多轮对话。

---

## 7.2 逐字生成

Agent 回复采用类似 ChatGPT 的流式逐字/逐段生成效果。

目的：

1. 提升自然聊天感；
2. 降低等待完整答案的体感；
3. 让用户感知 Agent 正在思考并回应。

该功能属于 MVP 核心交互体验。

---

# 八、Agent 核心工作流

Agent 不应直接采取：

> 用户问题 → LLM → 答案

而应采用：

> **学生问题 → 问题分析 → 能力边界判断 → 教材检索 → 教学策略决策 → 回复生成 → 对话记录**

---

## 8.1 Step 1：Problem Analyzer

首先分析学生输入。

需要识别：

### A. 学生真正想解决的问题

例如：

> “老师，我昨天去图书馆学习中文早上。”

表面上是在陈述一个句子。

实际上学生可能是在：

> 寻求句子纠错。

### B. 涉及的语言内容

识别：

- 词汇；
- 搭配；
- 语法；
- 句式；
- 语序；
- 量词；
- 补语；
- 表达自然度等。

### C. 错误位置

例如：

> “早上”

属于时间状语位置问题。

### D. 学生当前是否已经具备该知识

判断：

> 这个知识点是否在学生已掌握范围内。

如果已经学习：

> 应优先通过提示帮助学生回忆。

如果尚未学习：

> 不应假设学生已经掌握复杂规则。

---

# 九、教材检索机制

教材：

> 《发展汉语高级阅读1》

是 Agent 的重要教学依据。

## 9.1 检索目标

当学生出现具体语言问题时，Agent 应优先查找：

1. 相同语法点；
2. 相似句式；
3. 相同或相近表达；
4. 能用于解释当前问题的教材例句。

## 9.2 教材使用原则

### 优先级

**教材原句 > 基于教材结构改写 > Agent 自行生成**

如果教材中存在非常接近的例句：

> 优先使用教材原句。

如果教材例句过难：

> 可以保留语法结构，但替换为学生能力范围内的词汇。

如果教材没有合适内容：

> 再由 Agent 自行生成例句。

教材不能为了“引用教材”而被机械使用。

---

# 十、引导式纠错机制

这是整个 MVP 最核心的 Agent 教学机制。

## 10.1 核心原则

当学生出现错误时：

> **Agent 原则上不能第一次就直接告诉学生正确答案。**

而应该让学生自己完成。

---

## 10.2 引导阶梯

Agent 可以按照以下顺序逐步增加提示。

### Level 1：观察

提醒学生重新看自己的句子。

例如：

> “我明白你的意思。请你再读一遍自己的句子，特别注意‘早上’这个词的位置。”

---

### Level 2：规则提示

提醒相关语法规律，但不说答案。

> “在汉语里，表示时间的内容通常放在动词的前面还是后面呢？”

---

### Level 3：教材例句

提供相似例子。

> “想一想我们学过的例子：‘我每天早上七点起床。’‘每天早上’放在哪个位置？”

---

### Level 4：选项

如果学生仍无法完成：

> “你觉得应该是：A…… B…… C……？”

---

### Level 5：局部填空

进一步降低难度：

> “‘我昨天____去图书馆学习中文。’你觉得这里应该填什么？”

---

### Level 6：明确答案

只有在以下情况才直接给答案：

- 学生经过多次提示仍无法完成；
- 学生明确要求直接告诉答案；
- 当前问题已经无法通过引导继续；
- 简单事实型问题不适合继续设计引导。

即使给出答案，也必须说明原因。

---

# 十一、学生自我修正机制

Agent 不应把“学生最终收到正确答案”作为唯一成功标准。

更重要的是：

> **学生是否完成了自主修正。**

因此，每一次问题都应该尽可能形成：

> 发现问题 → 提示 → 学生尝试 → Agent 判断 → 再提示/确认 → 成功

---

# 十二、巩固机制

如果学生成功完成纠错，并且当前问题适合练习：

Agent 可以进行一次非常短的迁移练习。

例如：

> “很好。那我们再试一个类似的句子：‘请把门关。’你觉得‘关’后面应该加什么？”

学生：

> “请把门关上。”

Agent：

> “对了！这次你也自己找到了合适的补语。‘关上’表示动作完成后的结果。很好，继续保持这种判断方式。”

### 规则

巩固练习不是每次必须出现。

简单问题不需要强行练习。

---

# 十三、Agent 状态与记忆

因为产品只服务一个特定用户，因此可以进行较强的个性化。

## 13.1 长期记忆

系统应维护：

### 学生基础画像

- 当前水平；
- 目标水平；
- 教材；
- 学习目标。

### 已掌握内容

- 已掌握词汇；
- 已掌握语法。

### 错误历史

例如：

```text
时间状语位置
出现次数：5

量词
出现次数：3

把字句补语
出现次数：4
```

### 常见错误

系统可以逐渐形成：

> 学生常将时间状语放在动词之后。

之后遇到类似问题时，Agent 可以更加敏感地识别。

---

# 十四、推荐的 Agent 系统架构

MVP 不建议用一个超级 Prompt 完成全部任务。

建议采用以下逻辑：

```text
                    学生输入
                       ↓
              ┌────────────────┐
              │ Problem Analyzer│
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Knowledge Check │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Textbook Search │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │Teaching Strategy│
              └───────┬────────┘
                      ↓
              ┌─────────────────┐
              │Response Generator│
              └───────┬─────────┘
                      ↓
                    学生
                      ↓
               Conversation Log
```

# 十五、Agent Prompt 核心要求

System Prompt 应明确规定：

1. 你是该学生的 1v1 中文学习伙伴；
2. 当前学生为 HSK4，目标 HSK5；
3. 使用《发展汉语高级阅读1》作为重要教学依据；
4. 必须遵守学生能力边界；
5. 所有面向用户的内容必须使用中文；
6. 不允许在第一次出现错误时直接给出答案；
7. 优先使用提问、提示、规则、例子、选项、填空引导；
8. 学生多次无法完成时，再逐步增加提示；
9. 每次重点解决一个核心问题；
10. 在适合时进行一次迁移练习；
11. 不展示 Agent 内部分析过程；
12. **输出必须自然、亲和、鼓励，具有真实的 1v1 学习伙伴感；**
13. **鼓励必须结合学生具体表现，不得机械重复固定表扬。**
14. **所有面向学生的内容必须使用中文，不得使用印尼语。**

# 十六、推荐的内部结构化分析

Agent 每次处理问题时，可先形成结构化结果：

```json
{
  "student_question": "我昨天去图书馆学习中文早上。",
  "problem_type": "grammar",
  "error_type": "adverbial_word_order",
  "error_span": "早上",
  "grammar_point": "时间状语位置",
  "student_level": "HSK4",
  "knowledge_status": "known",
  "textbook_reference": "发展汉语高级阅读1",
  "scaffold_level": 2,
  "strategy": "rule_hint",
  "goal": "让学生自行调整时间状语位置",
  "tone": "encouraging_natural"
}
```

其中：

`tone`

用于提示 Response Generator 使用自然、亲和、鼓励性的交互风格。

这个结构化信息不直接展示给学生。

# 十七、聊天记录与数据系统

## 17.1 原则

不要只把整个聊天记录保存成一个 TXT。

建议：

> **数据库作为原始数据源，聊天文件作为定期导出结果。**

---

## 17.2 数据结构

### Conversation

保存一次完整对话：

- conversation_id
- user_id
- start_time
- end_time
- message_count
- resolution_status

### Message

保存每条消息：

- message_id
- conversation_id
- role
- content
- timestamp
- model
- response_time

### Agent Analysis

可进一步保存：

- problem_type
- error_type
- grammar_point
- vocabulary_point
- error_position
- textbook_reference
- scaffold_level
- resolution_status
- self_correction
- retry_count
- tone_strategy

### Student Profile

长期保存：

- language_level
- target_level
- known_vocabulary
- known_grammar
- common_errors
- learning_goals
- textbook_progress

本 MVP 预计连续运行两个月。

建议形成以下数据结构：

```text

2026-XX-XX.jsonl
2026-XX-XX.jsonl
...

weekly_summary.json

full_8_weeks.md

## 18.1 JSONL

用于后续机器分析。

一行代表一条消息。

用于人工阅读。

例如：

学生：

结果：
自主修正成功
```

# 十九、两个月数据的分析价值

两个月后，希望能够回答：

### 学生层面

1. 学生最常问什么问题？
2. 哪些语法点最容易出错？
3. 哪些词汇/表达反复出现问题？
4. 哪些错误在逐渐减少？
5. 哪些错误持续存在？
6. 哪些问题学生已经能够自主解决？

### Agent 层面

1. Agent 是否识别对了问题？
2. Agent 是否遵守了学生能力边界？
3. Agent 是否正确使用教材？
4. Agent 是否过早给出答案？
5. 学生是否能够在引导下完成修正？
6. 哪一种引导方式最有效？
7. **不同的语气与反馈方式是否影响学生的持续追问和自主纠错？**

# 二十、MVP 核心指标

因为第一阶段最重要的验证目标是：

> **Agent 是否真的解决学生的问题。**

因此不建议只用“日活”“聊天次数”作为主要指标。

## 核心指标 1：问题解决率

定义：

> 学生在一个问题交互中最终完成正确理解/正确修改的比例。

---

## 核心指标 2：自主纠错率

定义：

> 学生在未获得完整答案前，通过 Agent 提示自行完成正确修正的比例。

---

## 核心指标 3：首次提示成功率

定义：

> Agent 第一次提示后，学生能够正确修改的比例。

用于评价提示质量。

---

## 核心指标 4：重复错误率

定义：

> 同一知识点出现错误后，未来一段时间再次出现相同错误的比例。

如果重复错误持续下降，说明 Agent 不只是回答了问题，而可能正在帮助学生形成知识。

---

## 核心指标 5：互动体验指标

用于观察“中文学习伙伴”的人格和沟通方式是否合适。

可以通过聊天记录分析：

- 学生是否主动继续追问；
- 学生是否愿意尝试修改；
- 学生是否在错误后继续互动；
- 学生是否主动发起新的问题；
- Agent 的反馈是否过于模板化；
- Agent 的鼓励是否自然。

---

# 二十一、MVP 成功标准

两个月实验结束后，如果能够观察到以下结果，可以认为 MVP 基本验证成功：

### 体验层

学生愿意持续把中文疑问交给 Agent，并且在犯错后仍愿意继续尝试。

### 能力层

Agent 能够较准确识别：

> “学生到底哪里出了问题。”

### 教学层

Agent 大多数时候能够做到：

> 不直接告诉答案 → 引导学生思考 → 学生自行修正。

### 个性化层

Agent 能够结合：

> 学生水平 + 已掌握内容 + 历史错误 + 教材

生成不同于普通 AI 的回答。

### 互动层

Agent 的表达自然、亲和、鼓励性足够，但不会变成机械表扬或过度拟人化。

### 数据层

两个月的聊天数据能够帮助进一步回答：

> 这个具体学生究竟是在哪里学不会、为什么学不会、Agent 哪种干预方式最有效。

# 二十四、核心产品定义

最终，这个产品不是：

> **“一个可以回答中文问题的 AI。”**

而是：

> **“一个只服务于特定学生、了解其中文水平和学习历史、受能力边界约束、参考其教材，通过引导而不是直接给答案帮助学生解决中文问题，同时以自然、亲和、鼓励的中文陪伴学生学习的 1v1 中文学习伙伴。”**

整个 MVP 的核心闭环可以浓缩成：

```text
学生遇到问题
      ↓
随时向 Agent 提问
      ↓
Agent 判断“他哪里不会”
      ↓
判断“这是不是他已经学过的内容”
      ↓
从教材中寻找相关知识
      ↓
设计适合他的引导方式
      ↓
用自然、亲和的中文与学生交流
      ↓
学生自己尝试
      ↓
Agent 继续提供必要提示
      ↓
学生完成纠错
      ↓
Agent 给出具体、积极的反馈
      ↓
必要时进行一次迁移练习
      ↓
记录本次学习事件
      ↓
沉淀为该学生的长期学习画像
```

因此，MVP 真正需要验证的不是：

> **“AI 能不能正确回答中文问题？”**

而是：

> **“AI 能不能基于一个具体学生的能力边界和教材，通过自然、亲和的 1v1 引导，真正帮助这个学生解决他当下遇到的中文问题？”**
